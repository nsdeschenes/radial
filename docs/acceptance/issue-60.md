# Issue 60 acceptance evidence

Navaid Snapshot publication is a single DuckDB transaction. Candidate rows,
Cached Airport projections, metadata, the active marker, and removal of the
previous logical snapshot are committed together. Radial does not swap the
database file, delete its adjacent WAL, checkpoint as a publication boundary,
or infer the result of an unresolved commit.

## Evidence

| Promise                                                                                                                                                                                                 | Automated evidence                                                                                                                                                                                                                                                                      | Implementation evidence                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A hard process failure before mutation, during writes, after candidate verification, after the active-marker change, before commit, or immediately after commit recovers to one valid old-or-new state. | `recovers a valid old-or-new committed state after a hard kill …` in `src/acceptance/walCrashRecovery.test.ts` runs a real `nub` subprocess and `SIGKILL`s it at each barrier.                                                                                                          | `ProducerSchema.publishNavaidSnapshot` writes every candidate component and changes the marker inside one transaction; `src/acceptance/walCrashRecoveryWorker.ts` never repairs or swaps files. |

| Known producer failures preserve the previously committed state and leave no candidate storage.                                                                                                         | `rolls back an injected … failure without leaving candidate rows` covers transaction setup, transaction start, logical writes, candidate verification, active-marker change, and pre-commit boundaries; `does not mutate when publication gate acquisition fails` covers the gate seam. | `NavaidSnapshotPublicationError.activeDataPreserved` distinguishes failures before commit from unresolved commit outcomes, and rollback runs before the connection closes.                      |

| Existing source and derivation failures remain failure-safe.                                                                                                                                            | Existing OpenAIP capture, FAA source, candidate, WMM, application reload, and CLI failure suites continue to run in the full test suite.                                                                                                                                                | Acquisition and derivation remain outside the publication transaction; only a verified candidate reaches publication.                                                                           |
